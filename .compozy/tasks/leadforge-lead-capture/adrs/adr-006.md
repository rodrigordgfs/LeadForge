# ADR-006: Hybrid Site Audit (Playwright + PageSpeed Insights)

## Status

Accepted

## Date

2026-06-11

## Context

Digital diagnosis requires evaluating website presence, SSL, responsiveness, performance, SEO basics, and own domain. The user selected a hybrid approach: **Playwright heuristics** plus **Google PageSpeed Insights (PSI) API** for real performance metrics.

## Decision

Implement site audit in the `analyze` BullMQ worker with two phases:

**Phase A — Playwright (always when URL exists):**
- HTTP HEAD/GET for SSL certificate validity and redirect chain.
- Navigate URL in headless Chromium (desktop 1280×720 + mobile 375×667 viewports).
- Detect: page loads, viewport meta tag, basic title/h1/meta description, own domain vs. subdomain (facebook.com, instagram.com, linktree excluded as "not a real website").
- Classify `has_real_website: boolean` per PRD (Facebook/Yelp-only = no real website).

**Phase B — PageSpeed Insights API (when URL exists and Playwright confirms reachable):**
- Call PSI v5 API (`/pagespeedonline/v5/runPagespeed`) for mobile strategy.
- Extract: performance score, LCP, CLS, FCP, SEO score category.
- Requires `GOOGLE_PSI_API_KEY` env var (free tier: 25k queries/day).

**Score calculation** (`packages/shared/src/scoring/`):
- Weighted composite 0–100 from: website presence (30%), SSL (10%), mobile responsiveness (15%), PSI performance (20%), SEO basics (15%), social/Google Business signals (10%).
- Bands per PRD: 0–40 Critical, 41–60 Low, 61–80 Medium, 81–100 Excellent.

Leads with no URL skip Phase B; score heavily penalized (typically ≤ 40).

## Alternatives Considered

### Alternative 1: Playwright Only

- **Description**: Heuristic checks without external API.
- **Pros**: No API key, no rate limits, fully self-contained.
- **Cons**: Cannot measure real Core Web Vitals accurately.
- **Why rejected**: User wanted both A and B combined.

### Alternative 2: Lighthouse In-Process

- **Description**: Run Lighthouse programmatically inside worker.
- **Pros**: Full audit without external API.
- **Cons**: Heavy CPU/memory per audit, slow at scale, complex in Docker.
- **Why rejected**: PSI API provides same metrics with less worker load.

## Consequences

### Positive

- Real Core Web Vitals from PSI improve score credibility for sales pitches.
- Playwright handles "fake website" detection (social-only links).
- Shared Playwright browser pool with Maps scraper (sequential queue separation).

### Negative

- PSI API dependency and daily quota limits.
- Two failure modes (Playwright timeout + PSI error) require graceful degradation.
- Audit latency: ~10–30s per lead with both phases.

### Risks

- **PSI quota exhaustion**: Mitigate with daily counter, fallback to Playwright-only score with `psi_available: false` flag.
- **Playwright timeout on slow sites**: Mitigate with 15s navigation timeout; partial score from available signals.
- **PSI API key absent in dev**: Mitigate with mock PSI responses in development mode.

## Implementation Notes

- `SiteAuditor` interface in `packages/shared`.
- Store full audit result as JSONB on `leads.diagnosis_json`.
- Re-diagnosis after 30 days: compare `diagnosed_at` timestamp, allow manual re-trigger.
