# ADR-004: Playwright-Based Google Maps Lead Mining

## Status

Accepted

## Date

2026-06-11

## Context

The PRD requires mining public business listings by segment and geographic location in Brazil. The product owner explicitly chose **Google Maps + Playwright** as the data source and scraping mechanism. Alternatives include third-party Maps APIs (Outscraper, SerpAPI) or unofficial HTTP endpoints, which add cost or fragility without full control.

## Decision

Implement lead discovery via a dedicated **Playwright scraper worker** that:

1. Builds a Google Maps search URL from segment subcategory + city + state + optional radius.
2. Launches headless Chromium (Playwright Docker image: `mcr.microsoft.com/playwright`).
3. Navigates Maps, scrolls the results feed to load listings (target: up to 120 per search, paginated in UI).
4. Extracts from each listing card/panel: name, category, address, city, state, phone, website URL, rating, review count, Maps place URL.
5. Opens detail panels for leads missing website/phone to enrich WhatsApp and social links when visible.
6. Persists raw scrape results to PostgreSQL and enqueues `analyze` jobs per lead.

Scraper runs exclusively in `apps/worker` — never in the Next.js web process.

## Alternatives Considered

### Alternative 1: Third-Party Maps API (Outscraper, SerpAPI)

- **Description**: Pay-per-request API returning structured Maps data.
- **Pros**: No browser maintenance, stable schema, faster integration.
- **Cons**: Recurring cost per search, vendor dependency, rate limits on free tiers.
- **Why rejected**: User explicitly requested Playwright + Google Maps.

### Alternative 2: Google Places API (Official)

- **Description**: Official Google Cloud Places API for business search.
- **Pros**: Legal, structured, reliable.
- **Cons**: Requires Google Cloud billing, API key management, different data shape than Maps UI, cost at scale.
- **Why rejected**: User chose Playwright scraping; official API can be evaluated in Phase 2 as fallback.

## Consequences

### Positive

- Full control over extraction fields aligned with PRD data model.
- No per-request API fees for Maps data.
- Playwright reused for site audit (ADR-006), sharing browser infrastructure.

### Negative

- Scraping fragility when Google changes Maps DOM.
- CAPTCHA and rate-limit risk under high volume.
- Slower than API-based lookup; requires careful concurrency limits.

### Risks

- **DOM changes**: Mitigate with selector abstraction layer and scraper integration tests with recorded fixtures.
- **CAPTCHA/blocking**: Mitigate with concurrency cap (max 2 concurrent scraper sessions), random delays (1–3s between scrolls), session rotation.
- **Legal/ToS**: Mitigate with public-data-only extraction, LGPD compliance docs, no bulk re-export.

## Implementation Notes

- `MapsScraper` interface in `packages/shared` with `ScrapeSearchInput` / `ScrapedBusiness` types.
- Scraper module: `apps/worker/src/scraper/maps-scraper.ts`.
- Max 120 results per search job; store `search_jobs.total_found` and paginate in UI.
- Default radius: 10 km (resolves PRD open question #1 unless overridden in settings).
